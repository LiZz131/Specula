# 潜在 bug 记录

确认差异来自实现、而且可执行规格已经按库的控制流对齐之后，建一个目录，至少放进三个文件：

| 文件 | 内容 |
|---|---|
| `MC.out` | TLC `-tool` 原文，里面有 `pc` 和每一步的状态 |
| `traces.txt` | 生成器写出的控制器命令 |
| `log.host` | 控制器日志，含失败步的变量比较 |

同目录放一份 `README.md`，写四件事：

1. 配置名、种子、步号。步号用日志里的 `# [k]`。
2. 不一致的变量、节点、代码值、模型值。两边的值都写上。比较通过但两边一起偏离协议时，写偏离的变量和写入后的值。
3. 库里的位置：文件、函数、行号，以及该行做什么。
4. 为什么把它归成实现差异：规格的哪一条公式已经描述了这条路径，回放仍得到这个结果。

环境问题用同一份清单，并在开头写明这一步没有在节点上执行。连接断开、`check_has_recv_queue` 连续失败属于这一类。

目录放在 `<run>/potential-bugs/<短名>/`。新开一轮次时不要改这个目录。

交接给 `bug-confirmation` 时带上这个目录。确认和修复不在本 skill 里做。
