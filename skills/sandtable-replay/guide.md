# 受控执行与差异分类

`sandtable-instrumentation` 完成之后，用随机轨迹检查可执行规格和未改动的实现是否走出同样的可见状态。单条轨迹能回放，只说明生成器认识 `pc`。这一阶段要求每种建模配置都跑完约定的条数。

## 输入 / 输出

**输入**：`MC_for_sandtable` 和每一份 `MC_for_sandtable*.cfg`，容器里的 `run_one_testcase.sh`，节点数等于 `Cardinality(Server)`。

**输出**：

- 每种配置一个目录，里面是 `t001` … `t100` 的 `MC.out`、`test/traces.txt`、`test/log.host`
- 每条轨迹的判决和实现侧墙钟
- 潜在 bug 目录，格式见 `references/mismatch-record.md`

墙钟包住一次 `run_one_testcase.sh`，从启动控制器到日志结束。TLC 的时间另计，不写进这条耗时。

## 步骤

1. 按 `references/tlc-simulate.md` 为每种配置采样。默认每种 100 条，种子 `1` 到 `100`。行为里必须出现 `pc |->`。
2. 对每条 `MC.out` 执行 `run_one_testcase.sh <MC.out> <节点数>`。不要加 `-it`。节点数与模型里的 `Server` 相同。
3. 按 `references/compare-verdict.md` 判决。记下墙钟、是否 `logout`、变量断言、`net-len` 警告。
4. 变量对不上时先归类，再决定改规格还是写 bug 记录。
5. 适配层每改一处，六种配置的采样和回放全部重做。旧的覆盖率数字和轨迹目录改名保留，避免和下一轮混在一起。

## 归类

读失败那一步的 `pc`、`log.host` 里的代码值与模型值，以及库里对应的控制流。

**适配层。** 可执行动作或生成器没有发出库在这一步实际发出的系统调用，或盖错了序号、提交点、条目。原规格若已有这条分支，把 `Sand*` 收到驱动实际走的分支上。改完从步骤 1 重跑。

**潜在 bug。** 规格描述的是库的这条路径，代码的可见状态仍然不同；或者两边一致地做出规格标明的偏离。按 `references/mismatch-record.md` 留下 `MC.out`、`traces.txt` 和 `log.host`。规格保持不动，被测源码和驱动保持不动。

**环境。** 投递循环里连接被关掉、队列检查一直失败。变量差异是因为这一步没有在节点上执行。记录现象和日志位置，与协议赋值分开。

比较通过只说明这一步的可见变量相等。规格和代码一起写入一个偏离协议的值时，仍然记入潜在 bug，并附上该轨迹。

## 完成标准

每种配置的约定条数都有判决。适配层引起的变量断言已经消失，或者剩下一份写明原因的 bug 记录。覆盖率曲线交给 `sandtable-coverage`，它使用同一批回放。
