# 每个 action 都受控

`MCNext` 包含 `spec/base.tla` 的 `Next` 里的每一个 action。缺命令就在本轮的 SandTable 副本里补。不因为 stock 驱动还没有命令就把某一个留在外面，也不把协议公式改成 stock 驱动碰巧走的那一条。

某个系统上每个 action 对应哪条命令，写在该系统自己的例子里。本文件不列举某一个系统的 action 或变量。`examples/` 与本节冲突时以本节为准。

## 驱动只控制环境

被测对象是系统。驱动可以做的是环境：按序号投递、丢失或复制一条消息；在代表时间事件的 action 上拨钟；执行库自己调用的持久化回调；崩溃，以及从持久副本恢复。

驱动不写库用来做决定的内部字段，也不改库已经算出的结果。分支由库自己的状态加上这一步的输入决定。`label` 只提供这个输入，不替库选分支。

## 一次调用是一步

一次受控步等于事件循环的一次调用返回。这次调用在返回前发出的字节进入消息袋，属于这一步。不丢弃。不为同一批字节在后面的 action 再调用一次发送。函数内部不设等待来把一次调用拆成两个 action。同一进程在调用返回之前不能再跑另一个协议 action。

例外只用于崩溃窗口：持久化已经写完、发送还没有发生。可以在这个点等待，随后本节点只允许崩溃。等待期间不在本节点上跑别的协议 action。还没入袋的本地修改，别的节点看不见；那些 action 排在这次调用之前，或整次调用返回之后。

库在这次调用里发出了公式没有的字节时，停下对齐规格，使这些字节属于这一步。不丢弃来凑齐公式。

## 时间是事件

规格不写毫秒，也不写流逝时间。源码里「时间未到」写成对应的时间事件还没有发生。只在该事件的 action 上拨钟，拨到库自己会触发它为止。不把流逝时间或随机超时写进库的字段。随机时长由轨迹选择哪个节点先发生该事件来表达。

两个阈值若会走出不同的状态，就写成两个事件。不要在一个 action 里用选择去覆盖被一次拨钟跳过的窗口。

## 持久化

持久内容不按类型写死。读 `base.tla` 里崩溃与恢复的公式和注释，再对照系统源码：崩溃之后、恢复时仍然保留的变量，就是持久内容。被丢掉或按公式重设的，是易失内容。

写驱动时必须把持久内容真正写出去，并在恢复时读回来。不能为了省事只改进程内存。回调只返回成功、只留一个计数、或不留下可重读的副本，都不算做了持久化。公式写明某次赋值不持久化时，不要在驱动里补上。

## 崩溃与恢复

崩溃和恢复是 `Next` 里的 action，进入 `MCNext`。手动触发是允许的。

- 崩溃：停止该节点。已经写下的持久内容留在副本里。这一步成功不是失败。
- 恢复：从该副本读回持久内容，再按公式设置易失内容。不从被停掉的进程内存里把持久内容抄回来。公式要求保留、又没有写入副本的值，做不到就记适配失败，不要把这个 action 从 `MCNext` 里拿掉。

没有这两个 label 时进程退出、断言或 sanitizer，按 `sandtable-replay` 记失败类 `crash`。

## 与具体协议无关的控制

- 丢掉一条消息：按捕获序号丢掉这一条。清空整条通道不能代替它。
- 复制一条消息：按捕获序号再放入一份。
- 处理一条已经捕获的消息：按捕获序号投递这一条，再让该节点处理。

其余 action 的触发方式因系统而异，写在例子里。

cfg 里已有的次数界限，`MCNext` 继续读。不要写「某类场景没有执行」。
