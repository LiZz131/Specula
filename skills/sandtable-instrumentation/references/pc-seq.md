# pc 与 seq

`scr.pc` 是给生成器的命令元组，第一步是 `base.tla` 里的 action 名。`seq` 是发送序号，等于拦截器捕获数组的下标加一。

## 序号

同一步里，按实现发出这些消息的顺序盖章。节点集合等于模型的 server。不默认三个节点，也不默认名字是 `n1`、`n2`、`n3`。

`nSent` 加上本步公式发出的条数。丢失不增加 `nSent`。丢掉一条时，不改其余消息已经盖上的序号。

一条通道上同一步发出多条时，模型里更晚的消息用更大的序号。

## 与协议无关的命令

生成器用每一步**之后**的状态里的 `pc`。下面几类与具体协议无关。其余 action 的命令因系统而异，写在 `examples/<系统>.md`，不写在这里。未知的 `pc` 直接失败，不要猜一条命令。

| pc | 控制器做什么 |
|---|---|
| 崩溃 | 停止该节点。持久副本保留。这一步不是失败 |
| 恢复 | 从持久副本读回持久变量，再按公式写易失变量 |
| 丢失一条消息 | 按序号丢掉这一条。不要清空整条通道 |
| 复制一条消息 | 按序号再放入一份 |
| 处理一条已捕获的消息 | 按序号投递这一条，再让该节点处理 |

若某个 action 靠推进时钟触发，毫秒数写在该系统的例子里。不同 action 不要共用同一个毫秒数。

## 比较

每步比较哪些变量、持久变量和易失变量怎么比，见 `sandtable-replay` 的 `references/compare-verdict.md`。然后比较消息条数。
