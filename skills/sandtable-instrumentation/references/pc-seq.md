# pc 与 seq

`scr.pc` 是给生成器的命令元组，第一步是 `base.tla` 里的 action 名。`seq` 是发送序号，等于拦截器捕获数组的下标加一。

## 序号

同一步里，按这次调用实际发出的顺序盖章。条数等于公式这一步的发送数。库多发出公式没有的字节时，停下对齐规格，不用丢弃来凑齐条数，也不为同一批字节在后面的 action 里再盖一次序号。节点集合等于模型的 server。不默认三个节点，也不默认名字是 `n1`、`n2`、`n3`。

`nSent` 加上本步公式发出的条数。丢失不增加 `nSent`。丢掉一条时，不改其余消息已经盖上的序号。这里的丢掉是轨迹里的丢失 action，不是把库已经决定发出的字节扔掉。

一条通道上同一步发出多条时，模型里更晚的消息用更大的序号。

## 与协议无关的命令

生成器用每一步**之后**的状态里的 `pc`。下面几类与具体协议无关。其余 action 的命令因系统而异。`examples/<系统>.md` 如果已经存在，只读，不在这里重写。没有这个文件时，命令记在本轮目录。不要创建或修改 `examples/` 下的文件，除非用户明确要求写那一个文件。未知的 `pc` 直接失败，不要猜一条命令。

| pc | 控制器做什么 |
|---|---|
| 崩溃 | 停止该节点。持久副本保留。这一步不是失败 |
| 恢复 | 从持久副本读回持久变量，再按公式写易失变量 |
| 丢失一条消息 | 按序号丢掉这一条。不要清空整条通道 |
| 复制一条消息 | 按序号再放入一份 |
| 处理一条已捕获的消息 | 按序号投递这一条，再让该节点处理 |

若某个 action 靠推进时钟触发，毫秒数写在本轮目录的说明里，只表示足以让库自己触发这个事件。驱动不写库内部的流逝时间或随机超时。已有 `examples/<系统>.md` 时可以照着读，不要为了记下毫秒数去改那个文件。例子里若写着丢掉库已发出的字节，或写入库的内部字段来选择分支，以 `controllability.md` 为准。不同时间事件不要共用同一个毫秒数，以免一次拨钟触发另一个事件。

## 比较

每步比较哪些变量、持久变量和易失变量怎么比，见 `sandtable-replay` 的 `references/compare-verdict.md`。然后比较消息条数。
