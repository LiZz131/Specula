# 行分类

只给未覆盖的可执行行分类。次数大于 0 的行不进表。每一未覆盖行只进一个集合。单位是行，不是函数。按下面的顺序，命中就停。

谓词可以用现有 spec 的变量，也可以用常量，例如 `Server` 的个数、`MaxLogLength`。不能为了写成谓词去发明规格里没有的字段。

1. 这行只在初始化、销毁或配置时运行？是则 **D**。包括创建、`free` / `clear`、驱动在 `raft_new` 里直接写字段所以不会调用的 setter，以及驱动从不调用的 getter。销毁路径可能藏资源泄漏，注明即可，不为此往 `MCNext` 里加崩溃或恢复。
2. 这行是防御性代码？assert 失败臂、NULL 检查、错误返回（`return -1`、`return NULL`、`RAFT_ERR_*`）。只读 spec 变量再错误返回的，也算防御性，不进 A。
   - 守卫能写成谓词： **B**。
   - 写不出： **C**。
3. 这行改写已有 spec 变量（任期、投票、日志、提交点、快照点、角色、`nextIndex`、`matchIndex`）？是则 **A**。
4. 守卫能写成谓词，但这行不改写 spec 变量？是则 **B**。日志环形缓冲扩容属于这里。
5. 其余是 **E**。模型没有这些字段。成员变更属于这里。

A 的守卫若在当前常量下为假（三个服务器时「投票节点数等于 1 就当选」），集合仍是 A。下一步是另开一份配置，不是在同一配置上继续加 trace。

## 下一步

| 集合 | 下一步 |
|---|---|
| A | 先看现有动作里有没有这条赋值：同一变量、守卫对得上、写入的值是该动作产生的。对得上：加长 `DepthBound`、加种子，或另开常量配置，回到 `sandtable-replay`。对不上：变量已在规格里，缺的是这条赋值，写入 `scenarios.md` 交给 `spec_generation`。不在 `Sand*` 里补协议。 |
| B | 交给 TLC 找让守卫为真的状态。防御性的 B 期望看到 assert、错误返回，或协议状态被改坏。非防御性的 B 期望这行被执行。 |
| C | 白名单。不采样。 |
| D | 低优先级。不采样。销毁路径的泄漏等有销毁动作时再看。 |
| E | 写成场景交给 `spec_generation`：读写哪些状态、守卫是什么、现有 `Value` 或动作为什么产生不了。不在 `Sand*` 里补协议。 |

第一次分类不要写死代码。A 或 B 在放宽界限后 TLC 仍找不到使守卫为真的状态，才把该行的下一步改成「死代码」，并写上用过的界限。集合保持 A 或 B。确认之后，该行从调整后覆盖率的分子和分母去掉，摘要里单列死代码行数。

## 两个覆盖率

原始行覆盖率是 gcov 的数字：执行过的可执行行 / 全部可执行行。

调整后行覆盖率：分子仍是 gcov 里已经执行的行。分母是全部可执行行减去未覆盖的 C 和 D。已覆盖的行不分类，所以已覆盖的防御性代码和初始化代码留在分子和分母里。未覆盖的 E 留在分母里，成员变更没重做规格之前，这个数有上限。两个数并列报出。
