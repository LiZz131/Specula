Notes (manual review of the regex audit):
- HandleVoteRequest response_vote/response_granted: consumed by ResponseMatches(e, i), which TraceHandleVoteRequest calls.
- PreElect send_pre_vote_req.last_log: consumed via SnapshotLog in TracePreElect.
- HandlePreVoteResponse vote: the responder's own vote inside the RPC body. Engine::handle_pre_vote_resp never
  reads it (engine_impl.rs:530-533: "the grant is read from `vote_granted` rather than by comparing votes"), so the
  model does not represent it; it is retained in the trace as diagnostic input only. The probed vote that the
  runtime correlates on (candidate_vote) is consumed.
